# graduation-app

## 1. サービス概要（※最後に書いてOK）

- 仕事後のトレーニングで種目選びに迷い、続けにくくなっている30代男性のためのサービスです。
- 鍛えたい部位を選ぶと、おすすめ種目と「なぜその種目が良いのか」が分かり、納得して今日のメニューを決められます。
- 筋トレの効果を伝えることが目的ではなく、「迷い」と「納得できない状態」をなくして、続けやすくすることを軸にしています。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

これまで筋トレが続かなかった友人たちを何人も見てきましたが、やめていった理由として多かったのが「ジムや自宅で何をやればいいか分からず、毎回メニューを考えるのが億劫になった」という声でした。実際に誘った友人からも、「いろんな種目がありすぎて自分に合ったものが分からない」「結局いつも同じ動きばかりで飽きてしまう」といった言葉を聞き、最初の「種目選びの迷い」が大きなハードルになっていると実感しました。

そのため本アプリでは、まず「今日やる種目を迷わず決められること」を軸に据え、初心者が迷わずトレーニングを始められ、継続のきっかけを作れるサービスを目指します。

### 2-2. なぜそれが「気になった」のか

学生時代からトレーニングを続ける中で、しんどさや「またこれをやるのか」という気持ちを感じ、そのきつさに意義を見いだせないことがありました。一方で、動きの意味を理解して取り組んでいたときのほうが、トレーニングが続いた経験があります。

また、私は物事を無駄なく効率よく進めることを大切にしています。そのため、意味が分からないまま取り組むときつさを感じやすく、理由を理解して効率化を進めれば負担を減らせると考えました。そして効率化を進めるには、一つ一つの動きの意味やトレーニングの効果を理解することが必要です。それらを手軽に知ることができるアプリを開発しようと考えました。

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

トレーニングの種目を調べても、情報がばらばらで、何をやればよいか分からず迷ってしまう。

---

### 3-2. 本当に解決したい課題は何か

「なぜそれが困るのか？」を**最低3回**繰り返してください。

- なぜ？困る？
  調べるたびに違う種目が出てきて、どれを選べばよいか判断できず、手が止まってしまうから。
- なぜ？判断できない?
  「なぜその種目が良いのか」という理由が示されておらず、選ぶ基準がないから。
- なぜ？それが問題か？
  納得できないまま取り組むと、「これで合っているのか」という不安が残り、トレーニングがただこなすだけの作業になるから。

→ 本当に解決したい課題：種目選びに迷い、納得できないままトレーニングが作業になって、続かなくなること

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

年齢設定：
  - 年齢：30代 男性
  - 理由：30代は体力の衰えや体型の変化を実感しやすく、「何とかしなければ」と考え始める年代だからです。そのため、この時期に筋トレへ挑戦する人が多いと考えられます。まだ筋トレへの意識が高くない段階だからこそ、本アプリを通じて、筋トレに対する意欲を高めてもらいたいと考えました。

生活・状況設定：
  - 生活・状況：仕事に力を入れていた年代から少し余裕が生まれる年代
  - 理由：20代でキャリアの土台を築いた人が、30代になって生活に少しゆとりを持ち始め、「何か新しいことを始めたい」と考える世代を想定しています。ただし、そのゆとりは限られた時間です。本アプリでトレーニング内容を決める時間を短縮し、限られた時間を効率よく使えるようにします。

環境設定：
  - 環境：仕事が終わった後、自由時間でトレーニングすることを想定しています。
  - 理由：仕事後は、使える時間が限られているうえに疲れており、「今日は何をやろうか」と考えること自体が負担になりやすいからです。そのため、トレーニング中に種目選びで迷ったり、調べ直したりする時間を減らし、「なぜこの種目をやるのか」を理解したうえで、短時間でも納得して取り組める状況を想定しました。また、仕事後は「面倒だからやめておこう」と感じやすいため、理由が分かることで目的意識を持って続けやすくなると考えました。

---

### 4-2. 自分とユーザーの距離

- 過去の自分

理由：私自身が、トレーニングを「ただこなすだけ」になり、種目選びに迷って何をすればよいか分からなくなった経験があるからです。今の私は、トレーニングの意味を調べて理解しつつありますが、当時の私にはそれを知る手段がありませんでした。そのため、「あのとき理由が分かる仕組みがあれば迷わなかった」と思える、過去の自分のような人をユーザーとして想定しました。

### 4-3. 実際に使われる可能性について(需要・存在確認)

このアプリは、「実際に使う人がいそうか？」という視点で見たとき、どうでしょうか。

- まず最初に使ってくれそうな人は誰か？
  - 最初に使ってくれそうなのは、「過去の自分」のような人です。つまり、30代で体の衰えを感じて筋トレを始めたものの、種目選びに迷い、何をすればよいか分からなくなっている男性です。【身近な例:同僚・友人など】
- その人は、どんな場面でこのアプリを思い出すか？
  - 仕事後にジムや自宅でトレーニングを始める前、「今日は何をやろうか」と迷った場面です。また、種目を調べ直して情報がばらばらで混乱したときや、「この種目は本当に自分に合っているのか」と不安になったときにも思い出してもらえると考えます。
- それを置き換えてまで使う理由はあるか？
  - 理由はあると考えます。仕事後の限られた時間と気力の中で、調べ直す手間をなくし、「理由が分かる」ことで納得して迷わずトレーニングできるからです。ただし、既存の情報源を完全に置き換えるのではなく、まずは「種目を選ぶ場面」でこのアプリを使ってもらうことを目指します。

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

きっかけ(知る・思い出す場面)
30代になって体の衰えを感じ、「何とかしなければ」と筋トレを始めたものの、種目選びに迷ったり、調べるたびに違う情報が出て混乱したりした場面がきっかけです。【SNSや検索で「筋トレ 種目 選び方」などを調べたときに、このアプリを知る】ことを想定しています。その後は、仕事後にトレーニングを始める前の「今日は何をやろうか」と迷う場面で思い出してもらいます。

最初の一歩(登録・導入)
負担を最小限にするため、最初の操作は【鍛えたい部位(胸・背中・脚など)を選ぶ】だけにします。長い会員登録や細かい設定は後回しにして、選んだ直後に「おすすめ種目」と「なぜその種目が良いのか」がすぐ見られる形にします。仕事後の疲れた状態でも、数十秒で価値を感じられることを目指します。

続ける理由(習慣・必要性・価値)
続けてもらう理由は3つあると考えます。

- 必要性：トレーニングのたびに「何をやるか」を決める必要があり、そのたびに使う場面が生まれる。
- 価値：理由が分かることで、毎回迷わず納得してトレーニングでき、時間と気力の節約になる。
- 習慣化：【トレーニング内容の記録や、前回の続きから始められる機能】により、「アプリを開けば今日やることが決まる」状態を作る。

このように、「仕事後に開く→迷わず決まる→納得してやり切る」という流れを繰り返し体験できることが、継続につながると考えます。

### 5-2. それでも自分が作りたい理由

私自身、トレーニングを「ただこなすだけ」の作業にしてしまった経験があります。もっと鍛えたい部位を【YouTube・検索サイト・トレーニングアプリなど】で調べると、おすすめの種目はすぐ見つかりました。しかし、「なぜその種目が良いのか」まで説明されていることはほとんどありませんでした。

例えば、胸を鍛えたくて調べたところ、ベンチプレスとダンベルフライの両方が紹介されていました。どちらを選ぶべきか、それぞれ胸のどこに効くのかが分からず、判断できませんでした。しかも、調べ直すたびに別の種目が出てきて、結局何をすればよいのか分からなくなってしまいました。

既存のサービスは「何をやるか」は教えてくれますが、「なぜそれをやるのか」という納得感までは得られませんでした。ここに、私は物足りなさと違和感を覚えました。

トレーニングの意味を理解できれば、鍛えたい筋肉を意識しながら動かせるようになり、種目選びにも迷わなくなると考えています。その結果、トレーニングを続けやすくなるはずです。そこで、種目ごとの「理由」が分かるトレーニングアプリを自分で作りたいと思いました。

### 5-3. 差別化を「体験価値」で表現する

このアプリは、【どんな人】の【どんな瞬間】を一番助けるアプリですか？

- 私のアプリの差別化ポイント：
このアプリは、仕事後に疲れた状態でトレーニングを始める30代の男性が、「今日は何をやろうか」と迷った瞬間を一番助けるアプリです。

既存の動画や検索サイトでは、種目は見つかっても「なぜその種目なのか」が分からず、調べるたびに違う情報が出て迷ってしまいます。このアプリでは、鍛えたい部位を選ぶだけで、【その種目が良い理由】まで納得したうえで今日のメニューを決められます。

理由が分かるため、ジムで「これで合っているのか」と不安にならず、迷わず、狙った筋肉を意識しながらトレーニングに集中できることが、このアプリならではの体験です。

## 7. このアプリで実現すること

### MVPで作る機能

- **部位の選択**: 胸・背中・脚など、鍛えたい部位を選ぶ(登録なしですぐ使える)
- **おすすめ種目の表示**: 選んだ部位に対して、種目を数個表示する
- **理由の表示**: 種目ごとに「どこに効くのか」「なぜおすすめなのか」を短い文章で示す
- **今日のメニュー決定**: 気に入った種目を選んで、その日のメニューとして一覧で確認できる

### MVPで準備するデータの量

MVPでは、**3部位(胸・背中・脚)、各部位3種目、合計9種目**を用意します。

- **部位:** 胸・背中・脚の3つに絞ります。
- **種目:** 各部位につき、基本となる種目を3つずつ用意します。1つの種目に、「効く部位」「理由」「注意点」「出典」を紐づけます。
- **絞る理由:** このアプリの価値は「理由が正しいこと」にあります。私自身は専門家ではないため、1つ1つの理由を出典で確認する必要があり、最初から数を増やすと確認が追いつかなくなるからです。
- **増やす方針:** MVPで「理由が分かると迷わない」ことを確認できたら、肩・腕・腹筋などの部位と、各部位の種目数を増やします。

### 本リリースで作る機能

MVPで「理由が分かると迷わない」ことを確認できたら、継続して使ってもらうための機能を追加します。

- **トレーニング記録**: やった種目・回数・重量を記録し、前回の続きから始められる
- **目的別の提案**: 「体型を引き締めたい」「姿勢を改善したい」など、目的に合わせて種目と理由を提案する
- **環境に合わせた絞り込み**: ジム・自宅、使える器具や時間に応じて種目を絞る
- **振り返り**: 続けた日数や鍛えた部位を確認でき、継続の実感が持てる
- **会員登録・データ保存**: 記録を引き継げるようにする

## 8. このアプリの懸念点とその対策

### 懸念点：「理由」の内容が正しいか・信頼してもらえるか

- **何が問題になりそうか**
  表示する「なぜその種目が良いのか」という理由が、間違っていたり、情報源が分からなかったりすると、ユーザーに信頼されません。その結果、調べるたびに違う情報が出て迷う既存サービスと同じ状態になってしまう可能性があります。
- **なぜそう思うか**
  このアプリの価値は「理由が分かること」にあります。そのため、理由が不正確だったり、根拠が見えなかったりすると、アプリの存在意義そのものが失われます。また、私自身は【トレーニングの専門家ではない】ため、誤った説明を載せてしまうリスクがあります。
- **そのために考えている対策**
  - 理由は【書籍・論文・信頼できる専門機関の資料】など、出典が確認できる情報をもとに作成し、可能な範囲で出典も表示する
  - MVPでは種目数を絞り、一つ一つの理由を丁寧に確認してから公開する
  - 理由の下に「一般的な考え方であり、個人差があります」と注記し、断定を避けることで、誤解や過信を防ぎます
  - 【トレーニング指導の経験者に内容を確認してもらう】ことも検討しています

## 9. 今後の展開・発展の方向性

### 機能追加の方向性

記録が溜まるほど、「理由」が自分ごとになる方向に発展させます。

- **記録にもとづく提案**: 「先週は胸を鍛えたので、今日は背中がおすすめ」のように、これまでの記録から、バランスを考えた今日のメニューを提案する
- **目的別の提案**: 「引き締めたい」「姿勢を改善したい」など、目的に合わせて種目と理由を変える
- **変化の振り返り**: 続けた日数や、鍛えた部位の偏りを見て、「続けた結果」が分かるようにする

### UI・体験の改善

仕事後の疲れた状態でも使えるよう、操作の少なさを保ったまま改善します。

- 前回のメニューを1タップで再開できるようにする
- 理由の説明を、最初は一言で、気になる人だけ詳しく読める二段構えにする
- 慣れてきたユーザー向けに、理由の表示を減らして素早くメニューを決められるモードを用意する

### 機能以外の工夫

- **内容の信頼性を育てる**: 8の対策とつなげ、出典の充実やトレーニング指導の経験者による確認を、運用として続けます
- **ユーザーの声を集める**: 「この理由は分かりやすかったか」を一言で評価してもらい、説明の改善に活かします
- **他の人との関わり**: 将来的には、【同じ目的の人が選んだ種目や、友人との記録の共有】など、続けるきっかけになる関わりを検討します。ただし、まずは個人で使う価値を固めることを優先します

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails
- DB：PostgreSQL
- デプロイ先：Render
- 使用予定ライブラリ：Tailwind CSS(スタイリング)

---

### 10-2. 技術選定の比較検討

| 候補 | 採用/不採用 | 理由 |
| --- | --- | --- |
| Ruby on Rails | 採用 | ランテックのカリキュラムで学んでおり、基本的な構造(モデル・ビュー・コントローラ)を理解している。新しく言語から学ぶ必要がなく、期間内にMVPを完成させやすい |
| Next.js(React) | 不採用 | 人気で情報も豊富だが、カリキュラムでは扱っておらず、フロントとバックエンドを別々に設計する必要がある。今回の期間では学習範囲が広すぎる |
| Laravel(PHP) | 不採用 | Railsと同様にまとまったフレームワークだが、使用経験がなく、言語から学ぶコストがかかる |
| SQLite | 不採用 | 手軽だが、本番環境での運用や、本リリースの記録・会員データの拡張を考えると、PostgreSQLのほうが安心 |
| Bootstrap | 不採用 | 手早く整うが、見た目が画一的になりやすい。仕事後でも見やすい「操作の少ない画面」を細かく調整したいため、Tailwind CSSを採用 |

- **今回チャレンジしたい点:**
  カリキュラムで学んだRailsを使い、「部位・種目・理由・出典」というデータ設計から、自分のアイデアを一つのアプリとして完成させることに挑戦したいです。また、【Renderへのデプロイや、Tailwind CSSによるスマホ向けのレスポンシブ対応】にも初めて取り組み、公開まで通して経験したいです。
- **不安な点:**
  【カリキュラムでは扱っていない部分(モデル同士の関連づけ、本リリースで使う認証機能など)】で詰まり、見積もりより時間がかかる可能性があります。また、Renderの無料枠には、アクセスがないと起動に時間がかかるなどの制限があるため、事前に最新の条件を確認します。

---

### 10-3. キャッチアップ不足の懸念

キャッチアップ不足の段階では以下の懸念点があります。

1. **完成までのハードルが高い**
   使用する言語やフレームワークが異なるため、キャッチアップにかかる時間は個人差があるものの、一定の時間を要することが予想されます。
2. **Issueの見積もりが難しい**
   「どこまで理解していて、何が分からないのか」「調査にかかる時間」などが不明瞭な場合、開発期間内に完了することが難しくなってしまいます。
